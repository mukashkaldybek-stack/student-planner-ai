Student Planner — Agent Instructions

Project Purpose

Build a simple, beginner-friendly Student Planner web application that helps students manage academic tasks and deadlines.

Project Documentation

Before making changes, read:
	•	_docs/plan.md
	•	_docs/process.md
	•	_docs/task-template.md
	•	The relevant GitHub Issue
	•	The applicable instructions in _docs/team/

Technology Stack
	•	Python for application logic.
	•	Flask for the web application.
	•	SQLite for storing academic tasks.
	•	HTML and CSS for the user interface.
	•	pytest for automated testing.

Do not introduce additional frameworks, libraries, or dependencies without approval.

Development Rules
	•	Work on one groomed GitHub Issue at a time.
	•	Implement only the requirements in the issue.
	•	Follow the issue’s acceptance criteria and constraints.
	•	Keep changes small, clear, and easy to review.
	•	Validate user inputs and handle errors appropriately.
	•	Write or update automated tests for new behavior.
	•	Do not remove existing functionality without approval.
	•	Do not close an issue; leave it open for QA review.

Commands

Use the commands supported by the actual project setup.

Typical commands after the application structure and dependencies are created:
	•	Run tests: python -m pytest
	•	Start the Flask development server: python -m flask --app app run

If the project uses a different entry-point file or a virtual environment, follow the actual project configuration. Do not claim a command succeeded unless it was run successfully.

Dependencies
	•	Do not add or upgrade dependencies without approval.
	•	Use the project’s documented dependency-management method.
	•	Document approved dependency changes.

Code Quality
	•	Use meaningful file, function, and variable names.
	•	Write readable, maintainable code.
	•	Test relevant functionality after changes.
	•	Report actual test commands and results.
	•	Update documentation when necessary.

GitHub Issue Workflow
	•	Read the issue before starting.
	•	Follow the PM-groomed acceptance criteria.
	•	Implement and test the requested behavior.
	•	Commit changes regularly.
	•	Comment on the issue with a summary and test results.
	•	Leave QA verification and issue closure to the defined workflow.
